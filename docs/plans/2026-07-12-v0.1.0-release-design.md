# pinyin v0.1.0 发布设计

## 目标

将仍保留 PoC 命名和手工打包流程的仓库整理为可公开发布的 `pinyin` v0.1.0，并在验证通过后推送 `main` 与 `v0.1.0` 标签，由 GitHub Actions 自动创建包含 Apple Silicon 和 Intel 两种便携包的公开 Release。

## 命名策略

首个公开版本采用硬切换，不保留 `rime-poc` 或 `RIME_POC_*` 兼容层。Cargo 包、可执行文件、默认配置文件、环境变量、日志、临时目录、诊断输出、脚本、分发目录和压缩包统一使用 `pinyin` / `PINYIN_*`。无配置文件时的内置进入与退出字符串也统一为两个英文单引号 `''`。

仓库目前没有 tag 或 Release，因此没有需要维护的公开兼容契约。与只修改压缩包外观、或为旧 PoC 名称增加迁移层相比，硬切换能避免首发版本携带永久的历史包袱。

## 开源与第三方合规

项目代码采用 MIT 许可证，版权行使用 `Copyright (c) 2026 pinyin contributors`。仓库增加贡献指南、v0.1.0 发布说明和第三方声明。

便携包会实际分发 librime、Homebrew 动态库依赖以及 Rime 配置和词典数据。打包流程必须为实际复制的组件生成版本与来源清单，并收集相应的 LICENSE/COPYING 原文。项目 MIT 许可证和第三方许可材料都必须出现在压缩包中；必要声明缺失时打包失败，而不是生成不完整的 Release。

## 便携包结构

每个架构的压缩包包含：

- `pinyin` 可执行文件；
- `pinyin.toml` 默认配置；
- `run-listener.sh` 与 `run-listener-debug.sh`；
- `data/` 下的基础 Rime 数据；
- `lib/` 下的运行时动态库；
- 中文 `README.txt`；
- `LICENSE`、`THIRD_PARTY_NOTICES.md` 与 `LICENSES/`；
- 记录版本、架构和依赖的构建清单。

包名为 `pinyin-v0.1.0-macos-arm64.zip` 和 `pinyin-v0.1.0-macos-x86_64.zip`。当前版本继续使用临时签名，不声称完成 Apple Developer ID 签名或公证；README 明确解释辅助功能、输入监控和 Gatekeeper 边界。

## 自动化流程

普通 push 和 Pull Request 运行基础 CI：Rust 格式检查、Clippy、测试、Shell 语法检查以及本地转换冒烟测试。

推送 `v*` 标签后，Release workflow 先验证标签版本与 `Cargo.toml` 一致，再在 `macos-15` ARM64 runner 和 `macos-15-intel` runner 上独立构建。每个构建任务必须：

1. 安装 librime 并下载基础 Rime 数据；
2. 运行完整测试；
3. 生成便携包；
4. 用 `file` 验证二进制架构；
5. 用 `otool` 确认没有残留的绝对 Homebrew 动态库路径；
6. 解压到临时目录并运行 `--doctor` 与实际拼音转换；
7. 检查许可证、配置和中文包内说明均存在。

只有两个架构任务都成功，汇总任务才下载两份产物、生成 `SHA256SUMS`，并用 v0.1.0 发布说明创建 GitHub Release。任一架构失败则不创建半套公开发布。

## 错误处理与验证

所有打包与发布脚本使用严格错误模式，并对工具、Rime 数据、动态库、许可证、架构、版本和输出路径做显式检查。验证不仅检查命令退出码，也检查压缩包解压后的实际文件和可执行行为。

本地实现完成后，在 Apple Silicon Mac 上运行格式检查、Clippy、完整 Rust 测试、Shell 语法检查、转换冒烟测试和 ARM64 便携包构建审计。随后推送 `main` 与 `v0.1.0`，持续检查 GitHub Actions 到终态；Release 创建后重新下载公开资产，核对文件名、SHA-256、架构和基本运行结果，完成发布闭环。
