# pinyin v0.1.0 Release Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Turn the internal PoC into a consistently named, licensed, tested, dual-architecture macOS v0.1.0 release and publish it through GitHub Actions.

**Architecture:** Perform a hard rename from `rime-poc` to `pinyin`, then make the portable package the single release artifact contract. Separate normal CI from tag-triggered release orchestration; each architecture builds and audits its own archive before a final job creates the public release.

**Tech Stack:** Rust 2021, librime, Objective-C++/Cocoa, Bash, Homebrew, GitHub Actions, GitHub CLI.

**Step 1: Update the binary package contract**

Package `target/release/pinyin`, `pinyin.toml`, MIT `LICENSE`, third-party notices, release notes, and a Chinese `README.txt` under a `pinyin-v<version>-macos-<arch>/` root directory. Extract the version from `Cargo.toml`; reject a caller-provided version mismatch.

**Step 2: Collect runtime dependency licenses**

For every dylib copied from Homebrew, resolve its formula prefix, copy all available LICENSE/COPYING/NOTICE files into a uniquely named `LICENSES/<formula>/` directory, and record formula version, SPDX license identifier, homepage, and source path in `BUILD-MANIFEST.txt`. Include a repository copy of the Boost Software License when the bottle does not install it. Copy Rime data repository licenses and revisions from `data/packages/`.

Fail packaging when a copied runtime formula or Rime data repository has neither a collected license file nor an explicit repository fallback.

### Task 5: Add CI and dual-architecture release automation

**Files:**
- Create: `.github/workflows/ci.yml`
- Create: `.github/workflows/release.yml`

**Step 1: Add normal CI**

On push to `main` and pull requests, run on `macos-15`: checkout, install librime and shellcheck, install stable Rust with Clippy/rustfmt, download Rime data, then run:

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
shellcheck scripts/*.sh
bash scripts/test-conversion.sh
```

**Step 2: Add tag-triggered release jobs**

Use a matrix with:

```yaml
include:
  - runner: macos-15
    arch: arm64
  - runner: macos-15-intel
    arch: x86_64
```

Each job validates `${GITHUB_REF_NAME#v}` against the Cargo version, runs the full suite, builds the portable archive, calls `check-release-package.sh`, and uploads exactly one archive using `actions/upload-artifact`.

The final job uses `needs: build`, downloads both archives, checks that both expected names exist, creates `SHA256SUMS`, then runs:

```sh
gh release create "$GITHUB_REF_NAME" \
  --repo "$GITHUB_REPOSITORY" \
  --title "pinyin $GITHUB_REF_NAME" \
  --notes-file RELEASE_NOTES.md \
  pinyin-v0.1.0-macos-arm64.zip \
  pinyin-v0.1.0-macos-x86_64.zip \
  SHA256SUMS
```

Grant only `contents: write` to the release job.

**Step 3: Validate workflow syntax and action pins**

```sh
actionlint .github/workflows/*.yml
git diff --check
```

Expected: no workflow or whitespace errors.

**Step 4: Commit**

```sh
git add .github/workflows
git commit -m "ci: automate dual-architecture releases"
```
